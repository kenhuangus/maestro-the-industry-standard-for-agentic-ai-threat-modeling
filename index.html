The Framework

10 Layers, 3 Domains

One stack for the whole agent system — every component maps to a layer.

Definition CSA, 6 February 2025

  • MAESTRO expands to Multi-Agent Environment, Security, Threat, Risk, and Outcome — the CSA framework for threat modeling multi-agent and agentic AI systems.
  • v2.0 expands the stack from seven layers to ten, reorganized into three operational domains.
  • L1–L6 are the operational stack in Domains 1 and 2; L7–L10 run horizontally across all of them.

Domain 1

Infrastructure, Intelligence & Knowledge

L1–L3 — what the agent runs on, reasons with, and remembers.

Domain 1 Layers 1–3

  • L1 Infrastructure: the compute, network, storage and platform agents execute on — VPC segmentation, mutual authentication, egress filtering, EDR/XDR, HSM and secure enclaves. Threat L1-T01: infrastructure compromise via supply chain attack.
  • L2 Cognitive Core: LLMs, SLMs, vision and multi-modal models, plus pre-training data, fine-tuning and safety alignment (RLHF, Constitutional AI). Threats L2-T02 training data poisoning · L2-T03 prompt injection / jailbreak.
  • L3 Data, Memory & Knowledge: vector databases, RAG, knowledge graphs, short-term memory in the context window and long-term memory — context compression and memory optimization are distinct security concerns (Appendix C). Threat L3-T01: RAG poisoning.
DOMAIN 1 — OWNERS
L3 · Data, Memory & KnowledgeOwner: Agent Owner (AIC)
L2 · Cognitive CoreOwner: Model Provider
L1 · InfrastructureOwner: CSP
Domain 2

Environment & Execution

L4–L6 — where the agent plans, runs, and reaches the world.

Domain 2 Layers 4–6

  • L4 Orchestration & Coordination: inference, memory, planning, tool invocation and sub-agent coordination — LangGraph, Semantic Kernel, AutoGen, CrewAI. Threat L4-T02: goal hijacking via orchestration manipulation.
  • L5 Deployment & Execution: containers and Kubernetes, CI/CD, runtime sandboxing, canary deployments and rollback. Threats L5-T01 container escape · L5-T02 CI/CD pipeline compromise.
  • L6 Tools, Application, Environment & Ecosystem: MCP adapters, A2A endpoints, agent marketplaces, skill registries and third-party APIs — the STA domain's 16 controls govern the tool supply chain. Threats: tool misuse and malicious skills.
DOMAIN 2 — OWNERS
L6 · Tools, Application, Environment & EcosystemOwner: Tool Provider, for each tool interface
L5 · Deployment & ExecutionOwners: CSP + OSP
L4 · Orchestration & CoordinationOwner: OSP
Domain 3 · Horizontal

Agency, Governance & Accountability

L7–L10 span Domains 1 and 2 — they are not a top layer; they cut across every layer.

Domain 3 Layers 7–10

  • L7 Identity & Autonomy: non-human identity lifecycle, JIT short-lived credentials, agent-to-agent federation, delegation-chain traceability and human-in-the-loop escalation (controls IAM-01–18). Threat L7-T01: agent identity forgery.
  • L8 Safety & Security: behavioral guardrails, I/O validation, prompt-injection detection, hallucination detection, circuit breakers and red-teaming. Threat L8-T01: guardrail bypass.
  • L9 and L10: L9 runs OpenTelemetry telemetry, immutable WORM logging, SIEM/SOAR and drift detection (LOG-01–16); L10 sets policy-as-code (OPA, Cedar) and compliance mapping in the Trust Control Plane (GRC-01–15).
DOMAIN 3 — HORIZONTAL, WITH OWNERS
L10 · Governance, Authority, Accountability, Risk & ComplianceOwner: Agent Owner, as integrating governance authority
L9 · Evaluation, Monitoring & ObservabilityOwner: all roles, within their delivery layers
L8 · Safety & SecurityOwner: all roles share; Agent Owner integrates

Why v2

Three Problems in v1

Version 2.0 exists because the seven-layer stack misfiled three things.

Rationale What v1 got wrong

  • Foundation misplaced: infrastructure sat mid-stack at v1 L4; v2 puts it at L1, with runtime and deployment controls at L5.
  • One layer, three jobs: v1 L6 conflated identity, safety and governance — different owners, enforcement points and cadences; v2 splits them across L7, L8 and L10.
  • Identity had no home: v1 had no explicit layer for agent identity and autonomy governance; v2 adds L7.

The Method

Six Steps, Start to Verified

The v2 method (Doc 2, §10) — the same six steps, in order, every time.

Method MAESTRO v2.0, §10

  • Steps 1–2: decompose the system and map each component to the ten layers; then run layer-specific threat analysis from the §7 catalogs, documenting each threat in the 16-field template.
  • Steps 3–4: trace cross-layer propagation; select mitigations from the AICM, with ownership under the Agent 3SRM.
  • Steps 5–6: verify with behavioral test sets and drift thresholds — replay on any model, prompt, tool or policy change — then score and prioritize risk (§10.6).

Synthesis

Alongside What You Have

The redrawn map fits the practice teams already run.

Takeaways Three points to keep

  • It complements, not replaces: MAESTRO works alongside STRIDE and OWASP classifications — teams keep their existing threat catalogs.
  • The three-domain organization is aligned with the CSA AI Agent Reference Architecture (CSA, 2026).
  • Start with one system: map it to the ten layers and follow one cross-layer chain before scaling the method.
